Your infrastructure.
The whole Engram.

Memory, activity, agent connections, and opt-in public profiles. Run the core app without an Engram subscription.

1. Get the source

Download or clone the Engram repository. You will need Docker with Compose, disk space for PostgreSQL, and enough memory for the gateway and active workspace processes.

2. Configure and start

From the repository directory, copy the example configuration. Set a strong database password in .env before starting. Keep external service keys empty for local processing.

cp .env.example .env
# Edit .env and set POSTGRES_PASSWORD.
docker compose up --build -d

The app binds to your computer’s loopback interface on port 8080. Open the local address printed in the repository guide. Use a TLS reverse proxy before exposing it to a network.

3. Create an owner account

Use the admin command from the host. Replace the example email and workspace name with yours.

docker compose exec engram bun cli/engram-admin.ts \
  workspace create --name "My workspace" --email you@example.com

The command prints a temporary owner access token once. Open the app, choose “Use an access token,” and sign in. Store the token securely; create separate named connections for your agents.

4. Keep it yours

Back up the PostgreSQL volume, keep your software updated, and restrict database and admin access. Session cookies need HTTPS on a remote deployment. Email sign-in and chat connector OAuth require additional provider configuration; token-based access works without them.

Self-hosted mode does not contact Stripe, check a licence, or enforce a hosted trial. Optional external AI stays off until your workspace owner enables it and the operator configures a provider.
