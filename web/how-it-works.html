HOW ENGRAM WORKS

Useful context.
Ready for your next agent.

Think of Engram as a shared drive for agent context: memory pages, decisions, and project notes. MCP connects your agents to that common place. Personal and team workspaces let you choose what is shared.

01 / Connect

A workspace is the common ground.

Start with your hosted invitation or your own installation. In the console, open Connections and create one key for each agent. Each key belongs to a workspace; its permissions and the workspace’s policies control what it can do.

Run guided setup, select your agent, and paste the key at the hidden prompt. The CLI checks identity and tool discovery before writing the agent’s native HTTP configuration.

npx @ani-hq/engram-mcp setup

Restart or refresh your agent’s MCP connection, then use the connection-check prompt from setup. The getting started guide advances after successful agent contact, a real save, and a real recall. An unused key does not count as a connected agent.

02 / Remember

Give useful decisions a place to stay.

Ask your agent to remember a useful fact: a project convention, a choice you made, or an important lesson. Engram’s remember tool adds a dated entry to a topic page. Memory lives in readable pages, with tags, links, and a timeline.

“Remember this project decision: background-job retries must use a stable request ID.”

This example is a prompt for your connected agent, not an automatic capture rule. You can open Memory in the console to inspect what was actually saved.

03 / Recall

Different agent. Shared context.

Connect a second agent to the same workspace. Ask it to recall the saved decision. The recall tool searches the workspace and returns a small set of relevant snippets; the agent can request a page when it needs more detail.

“Recall our decision about background-job retries.”

Core storage, keyword search, and activity history work without optional external AI. A configured provider can add optional analysis, embeddings, or reranking only after the workspace owner enables external processing.

Memory tells you what stuck.
Activity tells you what was reported.

Engram records calls to its own memory tools. For work in other tools, an agent can call record_action with a summary, result, and optional run or resource. Use the console to filter the history by agent, tool, and result, or inspect a grouped run.

Directly observed Engram calls and agent-reported external actions remain distinct. External reports are unverified: a reported “completed” result is the agent’s claim, not independent proof from the external service. Task reporting is optional and is separate from connecting memory.

Devin: manual MCP configuration

Devin supports custom HTTP and SSE MCP servers with authentication configuration. Configure Engram’s canonical /mcp endpoint and its workspace credential in Devin’s server settings, following the official Devin MCP guide. Devin is a manual configuration path; Engram’s guided CLI does not configure it.

Chat connectors and other clients

Claude and ChatGPT connectors that require OAuth use the configured MCP connector sign-in flow. For hosted Engram, the canonical MCP endpoint is https://engram.ani.computer/mcp. Client features and authentication support vary; follow the connection guide for the exact client.

npx @ani-hq/engram-mcp doctor codex

The doctor checks identity and the tool catalog without changing configuration. For a self-hosted endpoint, use setup’s --host option and your installation’s canonical URL.

Your personal context.
A selected slice for the team.

Use a personal workspace as the shared home for your own agents. A team workspace is a separate place for context that teammates and their agents can read. Sending an agent straight to the team workspace makes its writes available there.

Open Sharing in your personal workspace and describe what belongs with a team or another agent. Engram proposes bounded excerpts from saved memories and captured trails. With separately enabled and available Jev processing, it can propose matches by meaning; otherwise the screen labels its text-match fallback. Suggestions can be wrong and do not grant access. Review and explicitly select the exact excerpts before approving.

A team receives only the approved snapshots alongside its existing team memory. An isolated agent connection uses a separate bearer credential at /mcp/shared and reads only its approved snapshots. Existing full-workspace connections keep their broader access; disconnect or revoke them separately. New or changed memories need a fresh review. Read the sharing guide for the model, or ask for help setting it up.

Revoking a reviewed share stops future service reads of those snapshots. Legacy standing rules remain an API capability and use separate matching and soft-deletion behavior. It cannot recall content that another person or agent already read or exported. The privacy notice explains those boundaries.

Sharing has a boundary.

People and agents in a team workspace share its memory and activity. Keep private material in a separate personal workspace; explicit sharing rules can copy selected content into a team. A workspace key does not create private compartments inside one team.

A connected agent handles requested results under its own service’s terms. The hosting operator can access underlying databases and backups. Read the privacy notice for the full data flow, or run Engram yourself when you want to operate the infrastructure.
