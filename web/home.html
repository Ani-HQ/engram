Keep the decision. Skip the catch-up.

You have agents for writing code, exploring an idea, and finishing the next task. Give them a shared place for the decisions and context worth carrying forward.

Memory that another agent can recall.

Save a decision in one agent, such as “Keep background jobs idempotent. Retries should use a stable request ID.” Later, in another agent, ask what you decided about background-job retries. Recall brings the saved context back into the conversation.

And a trail of the work.

Activity shows which agent saved or read context through Engram, alongside work an agent chose to report, such as opening a pull request. Reported work stays labeled as agent reported and unverified.

Engram observes its own memory calls. Work in other tools appears when an agent reports it. Connecting Engram does not silently monitor every conversation or tool call.

Share a little. Keep the rest yours.

Give your team selected decisions, or give an agent a separate read-only connection to approved context. You review the exact excerpts before sharing.

  1. Describe the slice.

    Choose a team or a separate agent connection, then say what belongs in the share.

  2. Review every excerpt.

    Suggestions can be wrong. Select and trim the proposed text, then approve the exact excerpts.

  3. Share a snapshot.

    The recipient gets the approved excerpts. New or edited memories need fresh approval.

A team workspace makes approved excerpts read-only shared memory for everyone authorized there. A separate read-only agent connection can search and recall only those excerpts. Existing workspace connections keep their broader access; disconnect or revoke those separately to limit an agent to the slice.

Connect. Remember. Recall.

Three moves to carry context from one agent to the next. Walk through the details

  1. Connect your first agent.

    Claim your invite by verifying your email, then open Connections and make a workspace-bound key. Guided setup keeps the token out of your shell history.

    npx @ani-hq/engram-mcp setup

  2. Save a useful decision.

    Ask the connected agent to remember a decision or a useful bit of project context, such as “Remember: use stable IDs for job retries.” It lands on a readable memory page.

  3. Continue with another agent.

    Connect another agent to the same workspace and ask it to recall that context, such as “Recall our decision about job retries.” Task reporting is there when you want a wider work history.

Questions

Looking for setup help? Start with the support guide.

What exactly do my agents share?

The memory pages and activity in the workspace they are authorized to use. Save useful context through Engram, then recall it from another connected agent. A separate workspace has separate memory storage and scoped access.

Does Engram automatically record everything?

No. It observes requests to its own memory tools. External actions appear when an agent or integration reports them, and those reports remain labeled unverified. A connection alone does not capture every tool call or conversation.

Do I have to change the agent I use?

Keep your existing MCP-compatible client. Guided setup supports Claude Code, Codex, Cursor, OpenClaw, Hermes Agent, Amp, Devin CLI, VS Code and Windsurf. Chat clients that need OAuth use their connector sign-in flow. See the connection options.

How do I get an invitation?

Hosted Engram is in closed beta. Ask for an invite on X. Open the single-use invite link and verify your chosen inbox; an email-bound invitation needs its invited address. New friend invitations include 60 days of unlimited knowledge transfers after verification. Jev is separate. Existing members sign in with email.

What lives on this shared drive?

Engram holds memory pages and project context: notes, decisions, and the useful details your agents save through MCP. Task activity appears alongside that memory. The shared-drive analogy describes a common place for agent context; it does not promise general file upload or automatic synchronization of every app.

Can I give an agent only part of my context?

Yes. Create a scoped share in Sharing, review the exact excerpts, and configure its separate read-only agent connection. If the agent already has a broader workspace connection, disconnect or revoke that separately. You can also share approved excerpts with a team; everyone authorized there can read them. See how scoped shares work.

Do scoped shares stay in sync?

A reviewed share is a fixed snapshot. New or edited source text needs fresh review and approval. Revoking a share stops future service reads through it; it cannot recall text someone already read or exported.

Can I run it on my own machine?

Yes. The MIT-licensed app includes the MCP gateway, memory, activity history, and web console. Docker Compose is the local starting point. You operate the infrastructure and any optional providers. Read the self-hosting guide.
